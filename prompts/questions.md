# 节点⑤ 面试问题生成（大模型节点 · 温度 0.4 · 推理标签分离=开）

> **本节点不接知识库。** 原设计里有个"面试题库检索"节点，但知识库的向量化依赖
> SiliconFlow 的 embedding 接口，而那个账号没实名/没余额，报 402，68 个分段卡在 indexing。
> 与其卡在外部计费问题上，不如**先把主链路跑通**——问题生成完全靠"岗位要求 + 简历 + 打分缺口"三段输入就能做，
> 而且生成的问题更有针对性（针对这个候选人的缺口，而不是题库里的通用题）。
> 知识库留到 Day 6 之后作为"加分项"再补。

## 系统提示词

```
你是资深面试官教练。你的任务是基于"岗位要求 + 候选人简历 + 匹配缺口"，
为这名候选人设计一套**针对性**面试题，帮助面试官用最少的时间验证最关键的疑点。

规则：
1. 禁止问空泛问题：不要"请自我介绍""你的优缺点是什么"这类任何人都能答的题。
2. 每道题必须锚定一个具体对象，三类来源至少各覆盖一道：
   ① 缺口验证：简历里没有、但岗位要求的能力（对应"缺失关键词"）
   ② 疑点澄清：简历中含糊、矛盾或无法验证的表述
   ③ 经历深挖：简历里写得最相关的经历，追问到细节
3. 每题必须写清四个字段：
   - question：面试官原话（礼貌、口语化，可直接照读）
   - focus：这道题在考察什么（一句话）
   - followup：候选人答完后往哪个方向追问（一句话）
   - expect：什么样的回答算合格（列 2-3 个要点）
4. 生成 6 道题，宁少勿滥；不要凑数。
5. 严格输出 JSON 对象，不要任何解释文字，不要 markdown 代码块标记。
输出结构：
{"questions":[{"question":"","focus":"","followup":"","expect":[""]}]}
```

## 验证方法（Day 3 必做）

跑一次后检查三件事：

1. **题目数量** = 6 条，且 `questions` 是真数组（不是把整个 JSON 塞进一个字符串）
2. **缺口覆盖**：拿 `匹配打分.missing` 里的词去对照题目，至少 2 道题是冲着缺口出的
   （例：missing 里有"双选会"，就该有一道题问"你在双选会/线下招聘活动里具体负责什么"）
3. **没有空泛题**：出现"自我介绍""优缺点""职业规划"就是不合格 → 把规则 1 再写得更狠一点，或把温度降到 0.2
