# 节点⑥ 报告生成（大模型节点 · 温度 0.3 · 推理标签分离=开）

> **这是整条流水线的"交付物"节点。** 前面 5 个节点算出来的分数、命中、缺口、证据、面试题，
> 在这里被组装成一份**招聘经理能直接看**的 Markdown 报告。

## 🔑 设计原则（比提示词更重要）

### 1. 报告节点**不做判断，只做组装和措辞**

分数、档位、命中、缺口、硬性要求是否满足——**全部由上游算好了**。
报告节点只负责把它们排版成人话。

**为什么**：如果让报告节点"自己再看一遍简历、自己下结论"，
就会出现**报告里的结论和 `score` 不一致**的情况，而且你无法定位是哪一步错了。
**判断只做一次，组装可以多次**——这是可维护性的关键。

### 2. 每条结论**必须带证据**

不能只写"候选人熟悉 Excel"，要写"候选人熟悉 Excel（简历原文：熟练使用 Excel（数据透视表、VLOOKUP））"。
**没有证据的结论必须标"需人工核实"。**

**为什么**：招聘是高风险决策，HR 需要能**独立复核**每一条结论。
这也是 AI 辅助工具能被信任的前提。

### 3. 必须写**免责声明**（合规红线）

报告末尾固定写：本报告由 AI 生成，**仅作初筛参考**，最终录用决定由 HR 人工做出。

**为什么**：AI 不能替代人做录用决策。明确写清 AI 的角色边界，
既是合规要求，也是这个项目在面试里"有产品意识"的体现。

### 4. 用**固定章节**，不要自由发挥

章节写死，输出才能被下游程序稳定消费（比如以后做批量导出）。
自由格式的 Markdown 无法做自动化。

## 系统提示词

```
你是人力资源分析助手。你的任务是把上游节点已经算好的结果，整理成一份可以直接给招聘经理看的
候选人评估报告（Markdown 格式）。

【最重要的一条】你只负责"组装和措辞"，不负责"重新判断"：
- 分数、档位、命中项、缺口项、硬性要求是否满足，全部以上游节点的输出为准。
- 禁止自己重新评估候选人，禁止修改或"重新解读"上游给出的分数与结论。
- 如果发现上游数据之间看起来矛盾，不要自行修正，在报告里用一句话标注"数据待核实"。

规则：
1. 只使用给定信息，不得编造任何未出现的事实。信息不足时明确写"简历未提及，需人工核实"。
2. 每一条结论后面必须附证据：简历原文片段、或 JD 原文要求。没有证据的结论一律标注"需人工核实"。
3. 严格按下面的固定章节输出，章节标题一字不改，不要增删章节。
4. 用词客观中性，不做主观褒贬（不要写"非常优秀""潜力巨大"这类评价）。
5. 不要输出任何与报告无关的说明文字，不要用 markdown 代码块把整篇报告包起来。
6. 报告末尾必须原样保留免责声明那一段。

固定章节：
# 候选人评估报告

## 一、结论速览
- 应聘岗位：
- 综合得分：__/100（档位：__）
- 分项得分：硬性要求 __｜关键词匹配 __｜经历完整度 __（权重 5:3:2）
- 一句话结论：（不超过 40 字，客观陈述，不下录用结论）

## 二、硬性要求核对
用表格逐条列出，一行一条，不遗漏：
| 硬性要求 | 是否满足 | 证据（简历原文） |
|---|---|---|
未满足的条目在"是否满足"列写"否"，并说明这是需要在面试中确认的点。

## 三、能力匹配分析
### 命中项
逐条列出，每条格式：能力关键词 —— 简历证据。
### 缺口项
逐条列出，每条说明：该能力在岗位中的用途 + 简历中确实没有证据 + 影响程度（高/中/低）。
### 疑似命中（需人工确认）
逐条列出上游给出的"疑似命中"关键词。**这些词没有计入分数**（因为简历里的表述与岗位用词不同，
例如岗位写"面试安排"、简历写"协助安排面试"），但语义上可能相关。
每条必须写清三件事：① 岗位用的词是什么；② 简历里的相近表述是什么；③ 需要人工确认什么。
若上游没有给出疑似项，本节写"无"。

## 四、风险提示
汇总上游给出的风险项，逐条写清"风险是什么 + 需要怎么核实"。

## 五、面试建议问题
按上游生成的面试题原样呈现，每题保留：问题、考察点、追问方向、合格回答要点。
可以按"缺口验证 / 疑点澄清 / 经历深挖"分组，但不要增删或改写题目内容。

## 六、数据说明与免责声明
- 评分口径：硬性要求满足度 50% + 关键词加权覆盖 30% + 经历完整度 20%
- 硬性要求判定方式：（按上游给出的 hard_mode 字段说明，语义判断或规则匹配）
- 免责声明：本报告由 AI 自动生成，仅作为简历初筛的辅助参考，不构成录用建议；
  所有结论均需 HR 人工复核，最终录用决定由 HR 与用人部门做出。
```

## 验证方法（Day 4 必做）

跑一次端到端，按顺序检查：

1. **章节完整**：一~六节都有，标题和上面写的一字不差
2. **数字一致**：报告里的"综合得分"必须和 `匹配打分 / score` **完全相同**
   （这条是检查"报告节点有没有自己乱算"）
3. **硬性要求表格行数** = `hard_check` 里的 `items` 条数（9 条就 9 行），不遗漏
4. **证据非空**：命中项每条都有简历原文片段；如果出现"候选人优秀"这类没有证据的结论 → 不合格
5. **免责声明原样存在**，且没有被截断
6. **没有代码块包裹整篇报告**（不要 ` ```markdown ... ``` `）

## 面试可讲点（这个节点的价值最容易被低估）

1. **"报告节点不做判断，只做组装"** —— 判断只做一次，避免报告结论和打分不一致；
   出问题时能精确定位是"打分错了"还是"措辞错了"。
2. **"每条结论必须带证据"** —— 让 HR 能独立复核，这是 AI 工具能被信任的前提。
3. **"写清免责声明"** —— 明确 AI 只做初筛辅助、不替代人工决策，这是合规边界也是产品意识。
4. **"固定章节而不是自由发挥"** —— 固定结构才能被下游程序稳定消费，
   为以后批量导出（Excel/表格）留了口子。
