# 20 组运行清单 · 使用说明

配套文件：`test\运行清单.csv`（结果记录表，用 Excel 打开）

## ⚠️ 最容易错的一步：输入框里填的是【文件里的内容】，不是文件路径

Day 5 实测时就错在这里——三个输入框被填成了：

```
jd_text        =  data\jd\jd_01.txt            ← 这是"路径"，只有 17 个字符
resume_text    =  data\resume\cv_01.txt
jd_json_fixed  =  data\jd_fixed\jd_01.json
```

模型收到的"JD"就是 `data\jd\jd_01.txt` 这 17 个字符，里面没有任何岗位信息，
所以它老老实实返回了「未说明 + 空数组」，白跑一次。

### ✅ 正确做法

```
打开文件 → Ctrl+A 全选 → Ctrl+C → 到 Dify 对应的输入框里 Ctrl+V
```

### ✅ 填完自检

| 输入框 | 应该有多少字 | 如果只有十几个字 |
|---|---|---|
| `jd_text` | 几百字（jd_01 是 259 字） | 就是填成路径了 |
| `resume_text` | 几百字（cv_01 是 492 字） | 同上 |
| `jd_json_fixed` | 一两千字（jd_01.json 约 1800 字） | 同上 |

---

## 🚀 更省事的办法：用「准备输入」脚本

双击 **`tools\准备输入.bat`**，输入用例编号（如 `01`），
它会**依次把三样内容复制到剪贴板**，每复制一样提示你去粘贴，按回车继续。

15 组 × 3 个输入框 = 45 次复制粘贴，交给脚本就不会再填错。

## 每组的三个输入分别来自哪

| 列 | 含义 | 来源文件 |
|---|---|---|
| `JD文件` | 岗位 JD 原文 → 粘到 `jd_text` | `data\jd\<JD文件>.txt` |
| `CV文件` | 简历原文 → 粘到 `resume_text` | `data\resume\<CV文件>.txt` |
| `档案文件` | 岗位档案（固化版）→ 粘到 `jd_json_fixed` | `data\jd_fixed\<档案文件>` |

**`档案文件` 这一列是空的**，说明这个岗位还没固化过（需要先跑一次才能生成档案）。
这时候 `jd_json_fixed` 留空即可——路由节点会自动回退用 `JD解析` 的结果。
那些用例考的是**行为**（不丢字段、不报错、不臆造），分数精度不影响判定。

### 怎么给一个新岗位固化

```bash
python tools\freeze_jd.py jd_03 "HRBP"
```

跑完之后：`data\jd_fixed\jd_03.json` 就出现了，把它填回 CSV 的「档案文件」列即可。

## 每组的判定标准

| 列 | 怎么填 |
|---|---|
| **期望行为** | 这是**主判据**。跑完报告后逐条对照，满足填「是」，不满足填「否」并写进备注 |
| **参考档位** | 这是**参考**，不是硬性标准。分数刻度是我们自己定的，拿它当标准答案等于自己证明自己 |
| `实际得分` / `实际档位` | 从 Dify 运行结果里抄 |
| `行为达标` | 看「期望行为」那一列的对照结果 |
| `档位是否合理` | 你自己判断：这个档位放在这个人身上合不合理 |

> **为什么要以行为为主判据**：
> "有没有给出关键词堆砌警告"是可证伪的客观事实；
> "应该得 72 分还是 68 分"是偏好。**评测要测事实，不要测偏好。**

## 跑完一组后自检两件事

1. **`岗位要求路由` 节点的 `jd_source`** 应该是 **`fixed`**（档案文件为空的用例除外）
   —— 这是"固化生效"的标志
2. **报告里应出现「疑似命中（需人工确认）」小节**
   —— 这是 `suspect` 变量通了的标志

如果第 1 条显示 `parsed`，说明 `jd_json_fixed` 没粘上；
如果第 2 条没有，说明报告节点的变量又出问题了，告诉我。

## 万一又出现「数据不足，无法评分」

v8 版本加了保护：**当 JD 或简历解析结果为空时，不再给分数**，
而是返回：

```
score = 0
level = 数据不足，无法评分
risk  = ⚠️ 数据不足，无法评分：… 最常见的原因是把文件路径当内容填进了输入框 …
```

**看到这个档位就说明输入没填对**，不是候选人不行。
（修这个之前，同样的空输入会得到 56 分「待定，需人工复核」——看起来像一个正常的评估结论，
这是最危险的一类错误：静默失败 + 貌似合理的输出。）
