# HR 招聘助手 Agent · 施工说明（扣子 Coze 版）

> 目标：8 天内做出一个**可演示、可讲清、有评测数据**的 HR 招聘助手 Agent，用于投递 AI Agent / 智能体搭建类实习。
> 平台：**扣子国内版 https://www.coze.cn**（免费、国内直连、无需梯子）
> 备选平台：阿里云百炼 https://bailian.console.aliyun.com （节点概念完全一样，可平移）
> 本地自部署 Dify：见 `C:\agent\README-安装步骤.md`，属于**加分项**，不阻塞主线。

## 1. 工作流总览

```
开始 → ①JD解析 → ②简历解析 → ③匹配打分(代码) → ④知识库检索 → ⑤面试问题生成 → ⑥报告生成 → 结束
```

| # | 节点名 | 类型 | 输入 | 输出 | 关键参数 |
|---|---|---|---|---|---|
| 0 | 开始 | 开始 | `jd_text`、`resume_text`、`candidate`(可选) | — | 三个都是 String；后两个可设"非必填" |
| 1 | JD解析 | 大模型 | `开始.jd_text` | `text`(JSON) | 温度 **0.1**；开启 JSON 输出 |
| 2 | 简历解析 | 大模型 | `开始.resume_text` | `text`(JSON) | 温度 **0.1**；开启 JSON 输出 |
| 3 | 匹配打分 | 代码 | `①.text`、`②.text` | `score`、`level`、`matched`、`missing`、`risk`、`detail` | 用 `code/score.py` |
| 4 | 面试题库检索 | 知识库检索 | query = `①`里的岗位名＋`③.missing` | `result` | TopK=4，最小匹配度 0.45 |
| 5 | 面试问题生成 | 大模型 | `②.text`、`③`、`④.result` | `text`(JSON) | 温度 **0.5** |
| 6 | 报告生成 | 大模型 | `①`~`⑤` | `text`(Markdown) | 温度 **0.5** |
| 7 | 结束 | 结束 | `report`、`score`、`level` | — | 页面直接展示 |

> 各节点提示词见 `prompts/` 目录，直接整段复制粘贴。
> 变量引用方式：在提示词里用 `{{节点名.变量名}}`，或在扣子的变量选择器里点选插入。

## ⚠️ 1.5　上表是**最初的设计稿**，与实际落地有差异（Day 3 更新）

这张表是最开始按扣子（Coze）画的，真正在 Dify 上搭完之后有几处不一样。
**以本节的"实际"为准**，上表只当设计意图看。

| 项目 | 设计稿 | **实际落地** | 原因 |
|---|---|---|---|
| 开始节点名字 | `开始` | **`用户输入`** | 建节点时改的名。**变量选择器里显示的是节点标题**，所以找不到"开始"这一项，要找「用户输入 / jd_text」 |
| 大模型温度 | `0.1` / `0.5` | 解析类节点 **`0`**，出题节点 **`0.4`** | 结构化解析要稳定；出题要一点多样性 |
| JSON 输出开关 | "开启 JSON 输出" | **没有这个开关** | 这个 DeepSeek 插件只支持 `response_format: text / json_object`，**不支持 JSON Schema**。改用「提示词约束 + 代码容错」 |
| — | — | **「推理标签分离」开** | 新增项。不开的话思考内容会以 `<think>` 混进 `text` 污染 JSON |
| 知识库检索节点 | 有（节点④） | **已去掉** | SiliconFlow 账号未实名/无余额，embedding 接口报 `402 Payment Required`，68 个分段卡在 indexing。**是计费问题，不是配置问题** |
| 面试问题生成输入 | 靠 `④.result` 题库 | **改成 JD + 简历 + 打分缺口** | 去掉知识库后反而更针对具体候选人 |
| — | — | **新增「硬性要求判断」节点** | 字符串匹配判不出"本科 满足 大专及以上"；且 `hard_requirements` 条数会在 4~7 间跳导致分母不稳。详见 `prompts/hard_check.md` |
| 变量引用写法 | `{{节点名.变量名}}` | **必须用变量选择器插入** | 手打的只是普通文字，运行时不会替换，会原样发给模型 |

### 实际的节点连接（Day 3 完成后）

```
用户输入.jd_text ──→ JD解析 ──┬──→ 匹配打分   (输入1: jd_json)
                              └──→ 硬性要求判断 ──→ 匹配打分   (输入3: hard_check_json)

用户输入.resume_text ─→ 简历解析 ──→ 匹配打分   (输入2: resume_json)
                     └→ 硬性要求判断

匹配打分 → 面试问题生成 → 输出
```

## 2. 逐步搭建

### Step 1　建工作流
扣子 → 工作空间 → 资源库 → **工作流** → 新建，命名 `hr-recruit-agent-v0.1`。

### Step 2　开始节点
添加三个输入变量：
- `jd_text`：String，必填，描述"岗位JD全文"
- `resume_text`：String，必填，描述"简历全文"
- `candidate`：String，非必填，描述"候选人姓名（可选）"

> 若你的版本开始节点支持 File 类型，也可以加 `resume_file`，再串一个"文档解析"插件；**先用粘贴文本的方式跑通最稳**。

### Step 3　JD解析（大模型节点）
- 模型：**`deepseek-flash`**（实际用的；设计稿写的"豆包"没采用）
- 提示词：见 `prompts/jd_parse.md`（推荐直接复制 `prompts/节点提示词汇总.txt`，是自动生成的干净版）
- 温度：**`0`**（设计稿写 0.1，实际改成 0 求稳定）
- **推理标签分离：开**（重要，否则思考内容会污染 JSON）
- 输出变量名：`text`

> ⚠️ 从 Step 3 起，本节剩余内容按扣子（Coze）写，与 Dify 实际操作已不同。
> **实际搭建请以 `prompts/` 下各节点的参数表和第 1.5 节的对照表为准。**

### Step 4　简历解析（大模型节点）
同 Step 3，提示词用 `prompts/resume_parse.md`，输入引用 **`用户输入 / resume_text`**
（设计稿里写的是 `开始.resume_text`，实际开始节点改名叫「用户输入」了）。

### Step 5　匹配打分（代码节点）
- 输入参数：`jd_json` ← `JD解析.text`；`resume_json` ← `简历解析.text`（类型都选 String）
- 输出参数：`score`(Number)、`level`(String)、`matched`(Array\<String\>)、`missing`(Array\<String\>)、`risk`(Array\<String\>)、`detail`(String)
- 代码：复制 `code/score.py` 全部内容

### Step 6　知识库
1. 资源库 → **知识库** → 新建，命名 `hr-interview-bank`
2. 上传 `data/jd/` 里的 15–30 条公开 JD，以及你自己整理的面试题库
3. 分段设置：**600 tokens / 重叠 80**（若只有"自动分段"就选自动）
4. 索引方式：高质量 / 语义索引
5. 工作流里加**知识库检索节点**，query 填：`{{JD解析.text}}` ＋ `{{匹配打分.missing}}`（拼接方式随界面提示）
6. 召回参数：**混合检索**，TopK = 4，最小匹配度 **0.45**

### Step 7　面试问题生成（大模型节点）
提示词用 `prompts/questions.md`，温度 0.5。

### Step 8　报告生成（大模型节点）
提示词用 `prompts/report.md`，温度 0.5。

### Step 9　结束节点
输出：`report`（← 报告生成.text）、`score`（← 匹配打分.score）、`level`（← 匹配打分.level）。

### Step 10　试运行 + 发布
点"试运行"，粘贴一段真实 JD + 一份自编简历 → 跑通后点**发布**，发布成 **Bot**，这样你会得到一个可分享链接，录 demo 时直接演示，体验最好。

## 3. 评测（Day 5）

打开 `test/评测表.csv`（Excel 可直接打开），20 条用例逐条跑，填"实际结果/是否通过/失败原因"。

跑完必须算出**四个数字**（面试必问）：
1. 匹配等级判断准确率
2. 平均处理耗时（秒）
3. 单次调用成本（元）
4. 失败率（%）

## 4. 演示与交付（Day 6–8）

- **Demo 视频 60–90 秒**：输入 JD + 简历 → 展示评分与报告 → 展示知识库召回的依据
- **GitHub 仓库**（结构已给你建好）：
  ```
  hr-recruit-agent/
  ├── README.md          ← 项目说明 + 架构图 + 评测结果表
  ├── prompts/           ← 四个节点的提示词
  ├── code/score.py      ← 打分代码
  ├── data/              ← JD 与简历素材（脱敏）
  ├── logs/              ← 每天的迭代日志
  └── test/评测表.csv
  ```
- **面试要讲的三个亮点**：① 用代码节点做打分而不是让模型直接给分（可解释、可复现、可调权重）；② 报告强制标注证据来源（降幻觉）；③ 有评测集和四个量化指标。
- **要提前想好的三个坑**：① 模型直接打分不稳定 → 你的解法；② 简历解析丢字段 → 缺失填"未说明"＋代码节点风险提示；③ 知识库召回噪声 → 调分段与阈值。

## 5. 合规红线（务必遵守）

1. **绝不使用真实他人的简历**，一律用自己编造/改编的样本
2. **API Key 不要写进代码、不要上传 GitHub**，用 `sk-xxxx` 占位
3. JD 属于公开招聘信息，可以使用；面试题库自己整理或改写，不要整段抄付费资料
